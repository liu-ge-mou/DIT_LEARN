# 可携带的接力记录

记录是当前事实的索引，不是聊天转录。合并进项目现有的进度文件，保留团队字段；不要强制采用相同文件名或把每次会话堆成长期流水账。

## 最小字段

| 内容 | 必须能回答的问题 |
|---|---|
| 当前任务与目标 | 正在完成哪一件事，完成标准是什么？ |
| 版本依据 | 在哪个分支、哪个基准提交上？是否还有未提交改动？ |
| 已完成与待完成 | 实际做了什么，仍有哪些步骤？ |
| 关键决定 | 为什么这样做？有现成设计或 issue 时链接原文。 |
| 验证证据 | 执行了什么命令，在什么代码/资料状态下，结果如何？未执行就写未执行。 |
| 接力依赖 | 哪些数据、素材、工具、技能、连接或本机配置仍需准备？ |
| 下一步 | 接手者首先打开哪个文件或执行哪个动作？ |

验证记录至少写出命令/手算或检查方法、运行目录、相关工具版本、代码或资料版本及实际结果；失败保留具体原因，未运行写明未运行。基准提交之后存在修改时列出相对文件路径，说明验证针对工作区还是已提交版本。只需要与当前任务有关的环境信息，不收集整机清单。

时间使用用户本地时区并标注偏移；判断新旧主要靠提交/文件对应关系，而非修改时间。文件引用使用项目相对路径，标识外部资料的稳定来源。不要将 Windows 用户名、盘符或本机绝对路径当成另一台电脑也存在的前提。

## 一份已填好的示例

下面展示字段的具体程度，内容为示例，不复制到实际项目冒充进度：

```markdown
当前任务：为 reports/weekly.tex 补齐图表，验收为编译成功且图表可读。
版本：feature/weekly-report；base_commit=6d7c8a9。
工作区：reports/weekly.tex 有未提交改动；不能仅凭基准提交恢复该改动。
已完成：正文整理、两幅图引用修复。
待完成：补齐第三幅图，编译并检查 PDF。
决定：继续采用项目既有 XeLaTeX 配置，原因见 docs/report-format.md。
验证：已运行项目定义的编译命令；缺少 inputs/experiment-03.csv，尚未通过。
接力依赖：CSV 未纳入 Git；从项目现有受控数据源获取，保存到上述相对位置。
下一步：获取 CSV 后运行 scripts/build-report.ps1，再检查第三幅图。
```

对于代码记录对应的测试；对于报告记录编译与视觉检查；对于数据分析记录数据版本和可复现步骤。不把“提交成功”当作任务验证成功。

教学项目保留三类事实：本轮实际讲解了什么、助手运行了什么、学习者提交了什么独立证据。实现和理解混合的待办应分别记录；不能凭现成源码或助手 PASS 将学习者掌握项勾选。沿用现有清单和交接文件的分工，不为此另建一套进度。

## 维持单一状态源

- 让状态文件链接长期设计、决定、任务或实验记录，只保留与当前恢复有关的摘要。
- 多任务并行时按任务/分支分别记录当前状态，再提供一个简短入口；不以设备名称强行划分永久进度。
- 若当前文件与记录不符，先检查 Git 与任务证据，再更正记录；不要照着过期的“下一步”重做已完成的工作。
- 记录不存放密码、令牌、私有配置内容或完整机器会话数据。必要环境变量使用变量名；来源只写获准披露的定位信息。
