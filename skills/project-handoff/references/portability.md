# 环境与特殊场景

按观察到的问题选择对应小节，不为所有项目增加同样的设施。

## Windows 和环境复现

- 实测 shell 与运行时。Windows PowerShell 5.1、PowerShell 7、WSL 的路径、编码和命令行为存在区别；沿用已有目标环境。不要修改整机执行策略来绕过脚本问题。
- 对带空格/中文的路径使用参数列表、PowerShell 调用运算符和 `-LiteralPath` 等可靠方式；从项目根目录解析相对路径。
- 沿用现有 `.gitattributes`。确需补充时按文件种类决定文本换行和二进制属性，避免无关的全仓格式变化。
- 使用项目锁文件和运行时版本要求。已经有 uv、Conda、npm 或其他工具时不要再引入另一套包管理体系。虚拟环境、`node_modules`、缓存和工具安装目录一般在目标端重建。
- 只有干净环境复现确实困难且项目接受时才建议容器或额外自动化。

## Git 与 OneDrive 等文件同步

项目位于同步文件夹是待评估线索，不代表已有损坏。检查多个设备是否同时操作同一个同步中的 `.git`。推荐每台设备使用独立克隆，通过 Git 远程协调版本；移动现有目录需要用户明确选择，不自动搬迁或清理。

用户坚持文件同步时，解释并发写入及 `.git` 元数据冲突的具体风险，结合其已有方式处理；不另外建立第二个互相竞争的同步流程。

## 外部数据、素材和文档

源码到达不代表任务输入齐备。对于 CSV、实验图片、模型权重、PDF、字体或大文件，记录所需相对路径、版本/校验依据、获准的来源和恢复方式。

已有 Git LFS、数据仓库或共享存储时沿用。为当前任务缺失的输入提出最小恢复步骤；不要因为文件大就擅自上传外部存储或改写仓库历史。小型纯文档项目可能只需说明字体、编辑器与导出命令。

## Codex 技能、配置和连接

用户级安装不保证另一台电脑已有相同技能。对任务真正依赖的技能记录名称、来源、所需文件和安装位置策略；按目标端支持方式放入个人技能目录或项目可发现目录。复用本技能时复制完整 `project-handoff` 文件夹，保留 `references/`、`scripts/` 和 `agents/` 的相对关系，不只复制 `SKILL.md`。

项目应携带共享约定和可复现配置。模型偏好、认证、设备路径、权限策略和插件连接属于本机或账号配置；不覆盖整个用户配置或同步包含令牌/会话数据库的 Codex 目录。`.env.example` 只包含非敏感示例值。

换机后打开的新会话可能需要从项目文件恢复上下文；同名聊天、相同账号、相同技能安装均不能单独证明文件或运行环境已经一致。正在运行的服务、端口、终端和后台任务需要分别检查，不视为 Git 可传输状态。

## 并行、冲突和过期记录

| 可观察状态 | 处理方向 |
|---|---|
| 只有一个设备活动，远程已确认最新 | 普通分支接力，尽量快进 |
| 两台设备同时做不同任务 | 各自任务分支，整合时验证；不要用伪锁文件保证互斥 |
| 远端和本地各有新提交 | 比较两侧改动，按团队规则整合，禁止强制覆盖来“同步” |
| detached HEAD 或托管 worktree | 保留提交；根据环境支持选择分支/导出/原生交接，不重建已有工作树 |
| 记录写已完成，但代码/资料缺失 | 核对分支、远程提交和文件来源，以实测修正状态 |
| 身份验证或网络失败 | 完成本地保存，给出具体恢复动作，不宣称远端已同步 |

在离线传输场景，可按需要使用经过检查的 Git bundle 或选择性文件包，列出未纳入版本控制的任务输入。bundle 不自动包含未提交文件或未跟踪数据；接收端仍需验证分支、资料、环境与当前任务。
